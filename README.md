# Security Log Investigation: Failed Login Analysis

## 📌 Project Overview

This project demonstrates a practical investigation of suspicious authentication activity using security logs.

The investigation focuses on a series of failed login attempts against a user account on a fictional corporate workstation. A successful login occurs shortly after the failed attempts, creating a pattern that requires further investigation.

The objective is to analyze the available security evidence, reconstruct the sequence of events, identify potentially suspicious behavior, assess the risk, and document the investigation using a structured security incident report.

This project uses simulated authentication logs for educational and portfolio purposes.

---

## 🎯 Investigation Objectives

The investigation aims to answer the following questions:

1. What happened?
2. When did the activity occur?
3. Which system was affected?
4. Which user account was targeted?
5. What source IP generated the authentication attempts?
6. How many failed authentication attempts occurred?
7. Was authentication eventually successful?
8. What makes the activity suspicious?
9. Could the activity represent password guessing or brute-force behavior?
10. What additional evidence should be collected?
11. What actions should security personnel recommend?

# 🧠 What Is a Security Log?

A security log is a record of activity generated by a computer, server, application, network device, or security system.

Examples include:

* Successful logins
* Failed logins
* Account changes
* Password changes
* Process execution
* Network connections
* File access
* Security policy changes
* Privilege changes

Security logs provide evidence that can help investigators understand what happened on a system.

For example:

```text
2026-10-06 08:31:12
WORKSTATION01
User: john
Event: Failed Login
Source: 192.168.1.50
```

This tells the investigator that an authentication attempt failed, but it does not by itself explain why.

That is where investigation begins.

# 🚩 Suspicious Indicators

Several characteristics make the activity worthy of investigation.

### 1. Repeated failures

Seven failed authentication attempts were recorded against the same account.

### 2. Short time period

The failed attempts occurred within approximately one minute.

### 3. Same source

All attempts came from the same source IP address.

### 4. Successful authentication afterward

A successful login occurred shortly after the failed attempts.

### 5. Possible password guessing

The behavior is consistent with a possible password-guessing or brute-force attempt.

---

# ⚠️ Important Analyst Consideration

Suspicious activity does not automatically mean malicious activity.

There are several legitimate explanations.

For example:

### Possibility 1 — Legitimate User

The user may have repeatedly entered an incorrect password before eventually entering the correct password.

### Possibility 2 — Credential Issue

The user may have been experiencing an authentication or keyboard-related problem.

### Possibility 3 — Automated Process

An application, service, or scheduled process could potentially be generating authentication attempts.

### Possibility 4 — Compromised Credentials

An unauthorized user may have attempted multiple passwords and eventually obtained the correct credentials.

The available evidence is not sufficient to determine which explanation is correct.

---

# 🧪 Investigation Hypothesis

### Primary Hypothesis

The authentication pattern may represent a password-guessing or brute-force attempt against the `john` account.

### Alternative Hypothesis

The activity may represent legitimate user authentication attempts caused by repeated incorrect password entry.

Additional evidence is required to determine which hypothesis is more likely.

# 🔍 Recommended Follow-Up Investigation

## 1. Identify the Source Device

Determine which device is associated with:

```text
192.168.1.50
```

Questions to answer:

* Is it an employee workstation?
* Is it a server?
* Is it a VPN endpoint?
* Is it an unknown device?
* Is the device authorized?

---

## 2. Verify User Activity

Determine whether the account owner was attempting to log in during the affected period.

The relevant time window is:

```text
08:31 – 08:32
```

---

## 3. Search for Additional Authentication Events

Review authentication logs for:

* Additional failed attempts
* Additional successful logins
* Other accounts targeted by the same source
* Other systems targeted by the same source
* Authentication activity outside normal hours

---

## 4. Investigate Post-Login Activity

Because authentication was eventually successful, investigate what occurred immediately afterward.

Potential evidence includes:

* Process execution
* Network connections
* File access
* Privilege changes
* Remote access
* Account changes
* PowerShell activity
* Command-line activity

---

## 5. Determine Whether Other Accounts Were Targeted

Search for activity from:

```text
192.168.1.50
```

against other accounts.

If multiple accounts were targeted, the likelihood of an automated password-guessing attack would increase.

---

# 🛡️ Recommended Security Actions

Depending on the results of the additional investigation, the security team may consider:

* Monitoring the affected account.
* Monitoring the source IP address.
* Reviewing endpoint activity.
* Reviewing authentication history.
* Confirming the legitimacy of the successful login.
* Resetting the account password if compromise is suspected.
* Enabling or enforcing MFA.
* Restricting the source device if malicious activity is confirmed.
* Escalating the investigation if evidence of compromise is discovered.

Actions should be based on evidence rather than assumptions.

# 📝 Investigation Conclusion

The investigation identified seven failed authentication attempts against the `john` account on `WORKSTATION01`.

All seven failed attempts originated from `192.168.1.50` and occurred within approximately one minute.

A successful authentication occurred shortly afterward.

The observed behavior is suspicious and could indicate password guessing or brute-force activity. However, the available evidence does not establish whether the activity was malicious or legitimate.

Further investigation is required to identify the source device, validate the user's activity, review additional authentication events, and analyze activity following the successful login.

### Final Assessment

```text
Classification: Suspicious Authentication Activity
Severity: Medium
Confidence: Moderate
Account Compromise: Not Confirmed
Further Investigation: Required
```
